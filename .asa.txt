fix(docker): restore the entrypoint the running container actually uses

Prod runs ENTRYPOINT=[docker-entrypoint.sh] CMD=[node server.js] on docker-asa-api, but
current main never COPYs that file into the image and never sets ENTRYPOINT, so a build
from this repo produces a ROOT container with no GID matching. The entrypoint was tracked
all along at docker/docker-entrypoint.sh; c7c4383 dropped the COPY/ENTRYPOINT lines and
left the comment that still describes them.

Without it the nodejs user cannot reach /var/run/docker.sock, which is how this API
manages the ARK servers at all.

Also: the script was CRLF in git (292 bytes), which makes /bin/sh fail with "not found"
once it IS copied in, so it is now LF with a .gitattributes rule to keep it that way; and
the healthcheck probes 127.0.0.1 instead of localhost, matching the fix prod carries
(inside the container localhost can resolve to ::1 and fail).

Verified locally, not assumed: docker build succeeds, the built image reports
ENTRYPOINT=[docker-entrypoint.sh] CMD=[node server.js], the file lands at
/usr/local/bin/docker-entrypoint.sh mode 755 with a LF shebang, and npm test is 61/61.
